# Home Agent Gate 控制中心与独立任务管理

> 2026-11-16 产品范围已确认：任务看板 + 运行概览；独立执行覆盖固定操作 + 注册脚本 + 定时。用户目标：借开源整理增加看板与控制中心，支持脱离 LLM 使用和配置。本文约定产品边界及实施顺序；字段、状态转换与接口契约仍需补齐，完成详细设计后进入实现。

## 1. 现状

- v0.1.0 已有多渠道、profile、会话续聊与交接、报告发布、Windows 进程守护。
- `src/server/panel.ts` 提供状态、日志、停止、切换、重置、交接、注入与直接发送。配置由 `src/config.ts` 从文件读取，尚无配置编辑界面。
- 同一聊天串行；没有 TaskStore、任务级 Worker 调度或任务级 Watchdog。
- Router / Worker 的目标是由 Router 负责接话、派活和汇报，Worker 按任务独立执行并支持并发；相关通用能力在本仓库实现。

## 2. 目标与基本原则

控制中心是直接可用的程序界面。未配置 LLM、模型离线或额度耗尽时，仍能启动、查看数据、管理人工任务、编辑配置、检查渠道及使用已配置的确定性操作。

- 控制中心、CLI、渠道命令及未来 Router 调用同一个应用服务层。
- 任务持久化、状态转换、排队、并发、超时、取消和操作记录由程序执行。
- LLM 是可选执行后端；由用户明确选择或后续 Router 调度。
- 工具与任务模板统一注册、按版本复用；LLM 阅读使用说明及规则，选择绑定并提交挂载计划；程序校验、记录并在调用时执行约束。手工配置和定时执行共用同一协议，详见 [`tools-and-tasks.md`](./tools-and-tasks.md)。
- 按钮、读取配置、保存配置、查看日志、变更任务状态等管理动作直接调用 API。
- 界面区分直接管理动作与会调用模型的动作，执行前能识别后者。
- 配置保持 schema 驱动：界面与文件共用校验规则；支持导入、导出、校验、变更预览；明确保存值与当前生效值。
- 敏感凭据单独存储；界面显示是否已设置、替换和清除入口，读取接口返回脱敏信息。

## 3. 建议产品结构

| 页面 | 内容 | LLM 依赖 |
|---|---|---|
| 概览 | 渠道连接、执行状态、排队任务、等待处理项、最近失败 | 无 |
| 任务看板 | 人工建任务、指派执行方式、筛选、详情、操作记录和产物链接 | 人工管理无；Agent 执行时需要 |
| 执行记录 | 每次执行的开始结束、日志、失败原因、取消和重试 | 读取与控制无 |
| 渠道 | 新建、配置、启停、连接检查、微信扫码绑定 | 无 |
| Profiles / 后端 | 工作区、人设、后端、模型及其参数；可用性检查 | 配置无；真实推理测试需要 |
| 工具 / 模板库 | 通用工具、任务模板、使用说明、版本、部署绑定与挂载规则 | 管理无；LLM 自动选择时需要 |
| 自动化 | 固定操作、注册脚本和定时任务，共用工具调用与挂载协议 | 依执行方式 |
| 系统设置 | 数据路径、监听地址、发布服务、配置导入导出和生效说明 | 无 |

首版包含任务看板、运行概览、固定操作、注册脚本和定时任务，确认记录见 §7。工具与任务模板的通用性、LLM 挂载协议和后端适配约束见 `tools-and-tasks.md`。

## 4. 关键设计约束

### 4.1 任务与执行分离

人工任务可创建、编辑和完成；选择执行器后才创建一次执行记录。一个任务可有多次尝试，重试生成新记录并保留旧记录。任务的业务状态与执行器的 running / succeeded / failed / cancelled 等运行状态分别建模。

看板移动由业务状态转换规则约束。取消执行必须取得执行器的取消结果；界面同步显示实际执行状态。外部副作用在重试前有可见说明，重启恢复以记录和执行器能力为依据。

### 4.2 应用服务层

从 `panel.ts` 对 Dispatcher 的直接依赖逐步提炼配置、渠道、会话、任务与运行管理服务。API、CLI、后续 Router 复用同一校验、权限和状态转换。前端只提交明确操作，运行逻辑留在服务端。

### 4.3 配置生命周期

配置流程为草稿 → schema 校验与跨引用校验 → 展示变更 → 原子保存 → 按能力应用。应用结果逐项标识“已生效 / 待重启 / 应用失败”。保存冲突通过配置版本检测；校验失败保留当前可用配置。停用仍有运行任务的配置时需说明运行任务的处理方式。

首次启动允许没有模型凭据和可用 profile；渠道绑定、人工任务和系统配置按自身依赖独立启用。连接检查与实际推理测试分开。

### 4.4 数据与界面

首版以单机单管理员为部署目标，默认本机访问。若确认包含远程控制，再完整设计登录、会话和访问控制。管理记录保存在服务端，浏览器只保存筛选与布局等偏好。任务量增长和并发写入方式在详细设计中确定存储选择。

## 6. 本轮边界

首版聚焦单机单管理员、明确操作、可追溯执行和现有渠道。多租户、插件市场、通用可视化流程编排、远程机器集群和桌面自动化归后续单独设计。新增通用能力进入 Home Agent Gate；个人 persona、凭据和生产环境配置由下游部署维护。

### 已确认范围对应的首版流程

1. 首次启动打开控制中心，设置数据目录，直接使用人工任务；配置后端和模型是独立的可选流程。
2. 创建任务时选择人工处理、固定操作、注册脚本或 Agent。选择 Agent 时要求选择可用 profile；其他执行方式按各自依赖校验。
3. 固定操作首批复用现有渠道直接发送能力。会话停止、重置和 profile 切换归控制中心的直接管理动作；跨后端交接和注入 Agent 消息标明会调用模型。
4. 注册脚本包含名称、可执行程序、参数定义、工作目录、环境变量引用、超时与并发规则。界面执行已注册脚本并填写参数，服务端通过参数数组启动进程；日志与退出码归档到执行记录。
5. 定时计划引用固定操作、注册脚本或 Agent 的执行模板，显式配置时区、触发时间和启停状态。每次触发创建可追踪的执行记录。计划保存、触发和重试由代码执行，Agent 类型的实际运行才使用模型。
6. 看板支持人工待办与自动执行任务；运行概览呈现执行队列、渠道状态、等待处理和最近错误。进入详情查看每次执行记录、日志与产物。

详细设计必须补齐：脚本参数类型与凭据引用、调度错过触发和重复触发策略、任务与运行状态映射、取消及重试语义、配置生效和回滚、存储并发、管理 API 的访问校验。

## 8. 验证计划

- 配置校验、凭据脱敏、跨引用、生效结果与并发保存冲突。
- 任务及运行记录 round-trip、状态转换、重复提交、取消和恢复。
- 无模型 / 模型失败时，人工任务与控制中心流程可用。
- 页面操作用真实浏览器验证；涉及看板拖拽时覆盖慢速手势、刷新及状态回读。
- 真实渠道和模型联调另记结果；测试假后端通过与真实联调分别报告。
